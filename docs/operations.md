# 解析与私有文件运维

## 解析范围

PDFBox 按页面位置读取文本 PDF，POI HWPF/XWPF 读取 DOC/DOCX。`sections-v2` 归一化全角文字，识别带编号的中英文章节及别名，依据机构/日期/项目标题分段。教育提取学校、专业/学位、时间及说明；实习提取公司、岗位、时间及说明；项目提取名称以及带明确标签的目标、本人职责、技术栈、困难、解决过程、成果和改进。专业采用词表，机构和岗位采用规则；复杂双栏、无明显标记或陌生机构仍需人工校对。

每个提取字段附原文 evidence，MATCHED 表示标签或格式匹配，REVIEW 表示候选识别，两者都需要核对。未明确归类的文字留在原文并给出 warnings；团队职责不会作为本人职责，缺失内容不生成。结果长度受现有表单约束限制，截取时提示，完整原文保留。

上传初次解析生成草稿；重新解析只更新候选，不覆盖已保存手填内容。前端候选面板默认“仅填入空白字段”：教育/实习按机构与时间匹配、项目按名称匹配；不按数组序号覆盖，多重匹配与未命名条目提示手动处理。可确定的新条目会追加。“替换全部草稿”先列出变更及清空内容，经二次确认才应用。两种方式都只修改页面，用户保存草稿后才持久化。

扫描件没有 OCR，文本为空、加密、不允许提取、损坏、页数或文字超限会进入 FAILED。失败原因使用统一脱敏提示，不返回解析器原始异常。失败仍保留文件，可以下载、重试或手工补充后确认。

同步解析发生在请求内，文件记录与 PARSING 状态先提交，解析结果后提交。手动保存过的草稿不会被解析重试覆盖。进程中断后，如 PARSING 持续超过 5 分钟，可由本人调用重试接口。初版无自动任务队列；高并发部署前应增加独立任务、租约与超时隔离。

## 写入与补偿

1. 先验证文件，再在事务内记录 WRITING 文件元数据与 UPLOADED 简历。
2. 随机存储键采用 CREATE_NEW 写盘，不覆盖已有文件。
3. 写入成功后改为 STORED，再开始解析。
4. 任何写入或状态提交失败，尝试将文件记录标记 CLEANUP_REQUIRED，简历标记 FAILED；不存在自动物理删除。

若数据库在写入后的整个补偿阶段也不可用，预先提交的 WRITING 记录仍保留 storage_key、owner_id 和 biz_id，可在恢复后人工核对。进程在 WRITING 中断也采用同一恢复流程。相关文件不可通过下载接口公开。

管理员或运维可以通过数据库负责人授权的只读查询排查：

```sql
SELECT id, owner_id, biz_id, storage_key, storage_status, created_at
FROM file_object
WHERE storage_status IN ('WRITING', 'CLEANUP_REQUIRED')
ORDER BY created_at;
```

此查询结果仅供运维，不应对前端返回。核对文件是否完整、业务关联与所有者是否一致，再决定恢复标记或清理；任何物理删除必须先取得用户确认。初版不提供自动清理命令或接口。

## 部署边界

私有目录应只允许应用服务账号写入，不允许其他进程添加符号链接，不挂载为 Web 静态资源。下载校验数据库归属、业务关联、文件状态和文件存在性，响应 attachment、no-store、nosniff。

生产应通过 HTTPS 入口部署，配置连接池与数据库 TLS，按环境设定 CORS、登录限流和解析进程资源限制。本初版未接入统一网关、验证码、分布式限流、OCR、外部对象存储或 AI 服务。

JWT 签名材料必填且至少 32 字节；应用不记录密码、完整 JWT、简历正文或物理路径。退出撤销记录及文件元数据暂不自动清理，保留期限待团队确认。
