# 面序前端

基于已确认的第二版视觉稿，使用 Vue 3、TypeScript、Vite、Element Plus、Axios、Vue Router 与 Pinia。白底、深绿、黄色主按钮，桌面采用顶部导航与宽卡片，手机采用单列布局。

## 启动

需要 Node.js 20.19+ 或 22.12+，推荐 Node.js 24。先启动现有 Spring Boot 后端（默认 8080），再执行：

```powershell
cd frontend
npm ci
npm run dev
```

访问 `http://127.0.0.1:5173/`，注册学生账户后即可使用。后端启动方式见[本地验收与团队联调](../docs/team-test.md)。

开发服务器 `/api` 请求代理到 `http://127.0.0.1:8080`，所以不需要修改后端 CORS。若后端端口不同，在当前终端设置后执行启动命令：

```powershell
$env:API_TARGET = 'http://127.0.0.1:8081'
npm run dev
```

不创建或修改 `.env`。密钥和数据库凭证均由后端处理，不进入前端。

## 页面

| 路由（位于 # 后） | 功能 |
| --- | --- |
| /login、/register | 登录、学生注册、密码规则、错误提示 |
| /resumes | 本人简历分页、当前页状态筛选、上传、继续校对、项目入口 |
| /resumes/:id | 原文、授权 PDF 预览、教育/技能/实习/项目编辑、草稿、确认、重试、原文件下载、版本记录 |
| /projects | 按简历选择已确认项目、详情、选择校验、获取和下载确认快照 |
| /demos | 按岗位浏览已发布的典型示范与面试流程 |
| /training、/training/:id | 普通训练选题、草稿、录音、作答与逐题反馈 |
| /practice、/practice/:id | 专项训练、复练、暂停恢复 |
| /formal | 选择已确认项目，强制录音、计时和项目追问 |
| /reports、/reports/:id | 会话历史、报告、五维评分与复练 |
| /profile | 本人昵称、邮箱、电话、学校和专业 |
| /admin/users | 管理员分页、基础详情、昵称与学生状态维护；无私有简历访问入口 |
| /admin/content | 岗位、分类、题库、示范与评价规则 |

JWT 仅保存于当前标签页 sessionStorage，页面刷新后重新请求本人身份。退出成功后清理会话；401 或账号禁用会返回登录页。前端路由只用于展示控制，真正的数据权限仍由后端校验。

保存草稿会回到 DRAFT；确认时至少一个项目，名称和本人职责必填。失败解析允许手工补充。编辑使用 expectedRevision，冲突保留本地输入并提示重新加载；有未保存内容时离开页面会询问。

简历卡片和详情页提供“删除简历”，确认文件名和影响后执行逻辑删除；不会物理删除原文件，上传/解析中禁止删除。MySQL 后端需先应用 `backend/db/mysql/003_resume_soft_delete.sql`。

校对页“查看解析候选与填表建议”显示候选、来源、警告和差异。默认只填空白字段并保留手填内容；替换全部草稿需二次确认；应用后需要手动保存。旧简历先保存草稿再重新解析以获得新版候选。确认过的简历若需重新解析，先修改并保存草稿使其回到待确认状态。

- 个人资料未修改时禁用保存，修改后显示未保存提示；登录、注册和个人资料表单在提交期间禁用编辑。
- 统一按钮、输入框、辅助文字、键盘焦点与状态标记；修复 320px/390px 窄屏布局，管理员表格在手机上横向滚动，避免固定操作列遮挡资料。

样式加载顺序为 `style.css` → `responsive.css` → `polish.css`。`polish.css` 是本轮调整入口，其中有 Element Plus 的全局覆盖；其他成员接入新页面时需一起检查按钮、表单、弹窗和移动布局。

正式运行可使用[初版发布包](../README.md#初版发布包)。调试时仍可按上方步骤连接后端，自行注册账号；临时界面预览服务和示例登录方式不包含在仓库中。

新增 `npm run test:merge`（Node 22.6+）验证填表合并规则，`npm run test:resume` 使用接口夹具验证填空、替换、移动候选面板与删除确认，不连接数据库。
`npm run test:resume:live` 验证真实后端和 MySQL：创建合成学生与 PDF，解析、填空、保存、确认、逻辑删除并检查访问拒绝；不物理清理文件或数据库记录。

项目选择结果可下载 JSON 快照，不在浏览器持久化。要开始正式模拟，请前往「正式模拟」并选择本人当前已确认的项目。

## 验证

```powershell
npm run build
npm run test:merge
npm run test:states
npm run test:resume
```

- `build`：TypeScript 检查与生产构建，输出 dist/。
- `test:merge`：5 项填表合并规则测试，不需要运行浏览器或后端。
- `test:resume`：10 项解析候选、应用差异、移动布局及删除确认检查，使用模拟接口。
- `test:e2e`：使用本机 Edge 无头浏览器，访问真实后端及 MySQL，注册两个合成学生账户、上传合成 PDF，验证学生全流程。真实测试数据保留，不自动删除。
- `test:states`：使用明确标记的接口夹具，验证管理员状态维护确认、昵称编辑、移动布局、解析失败、并发版本冲突及会话失效；不修改数据库，不能替代真实管理员端到端验收。

`test:states` 与 `test:resume` 需要先运行 Vite，API 由各自脚本模拟。本轮这两组共 22 项通过，连同 5 项合并规则测试共 27 项；另有 22 项界面专项检查，结果见截图目录中的记录。

真实后端与 MySQL 已准备好、且允许创建测试数据时，再按需执行：

```powershell
npm run test:e2e
npm run test:resume:live
```

脚本默认访问 5173，可通过进程环境 `FRONTEND_URL` 改变。测试依赖本机已安装 Microsoft Edge，不会下载或安装全局浏览器。每次测试报告与截图使用独立时间目录，位于 test-results/，不执行目录清理。密码随机生成，仅在进程内使用，不写入测试报告。

## 构建与部署

生产环境将 dist/ 静态文件交给 Web 服务托管，并将同源 `/api` 反向代理到后端。使用 Hash 路由，无需为每个前端路径配置回退。Vite 的 `preview` 仅供本地查看构建文件，生产反向代理需要由部署环境配置；本次未修改后端或现有部署。

Element Plus 目前采用完整注册，构建会提示组件库分块超过 500 kB；功能和构建不受影响，可在后续按需引入以优化体积。

## 已知边界

上传限制按后端初版默认值 10 MiB；若服务端配置变更，应同步调整前端提示及校验。Word 原文件提供鉴权下载，浏览器内嵌预览只适用于 PDF。无 OCR、真实训练会话或 AI 评价页面。

简历状态筛选只作用于当前分页，页面明确提示范围；项目简历选择器也有分页，不会把单页数量误报为全站数量。
